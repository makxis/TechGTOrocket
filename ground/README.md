# Наземная станция ВРО-1

Программа принимает телеметрию от ракеты по радиоканалу, показывает,
что с ракетой происходит, и сохраняет всё принятое в файл.

Пункты 24, 25 и 45 ТЗ.

---

## Что понадобится

| Что | Зачем |
|---|---|
| Радиомодуль HC-12 | принимает сигнал от ракеты |
| Переходник FT232RL | подключает радиомодуль к компьютеру по USB |
| Компьютер с Python 3 | на нём работает программа |

Для проверок на столе вместо переходника годится вторая плата RocketBoard
с HC-12 и программой-мостом `tools/hc12_setup` (см. `docs/RADIO.md`):
всё, что модуль принял из эфира, она отдаёт в USB. Так радиоканал
проверялся 28.09.2026. Штатный приём на пуске — через FT232RL.

Радиомодуль соединяется с переходником четырьмя проводами:

```
HC-12          FT232RL
  VCC   ------   5V
  GND   ------   GND
  TX    ------   RX
  RX    ------   TX
```

Приёмник и передатчик перекрещиваются: TX одного идёт на RX другого.
Это самая частая ошибка при сборке.

---

## Установка

Нужен только Python 3.8 или новее. Библиотека `pyserial` лежит в проекте
(`ground/vendor/`), `pip install` и интернет не нужны.

**Windows:** поставить Python с https://www.python.org/downloads/, при
установке отметить **«Add python.exe to PATH»**. Окно (`tkinter`) входит
в состав Python.

**Debian и Ubuntu:** для окна `sudo apt install python3-tk`.

---

## Как пользоваться

Порядок из п. 25 ТЗ.

1. **Подключить** наземный HC-12 через FT232RL к USB-разъёму компьютера.

2. **Запустить** программу. В Windows — двойной щелчок по
   `НАЗЕМНАЯ СТАНЦИЯ.bat` в корне проекта. В Linux:

   ```sh
   python3 rocket_ground.py
   ```

3. **Выбрать порт** в списке сверху. Переходник программа узнаёт сама и
   поднимает его в начало списка с пометкой `[переходник]`. Если списка
   нет, нажать «Обновить».

4. **Нажать «Подключиться».**

5. **Убедиться, что данные идут.** Кружок слева должен стать зелёным, а
   надпись рядом — «данные поступают». Если кружок красный, значит порт
   открыт, но ракета молчит.

6. **Запустить ракету.**

7. **Наблюдать телеметрию.** Крупно показываются состояние полёта,
   текущая и максимальная высота, давление и состояние системы спасения.
   Внизу идут события: старт, апогей, раскрытие парашюта, посадка.

8. **После полёта** открыть журнал кнопкой «Открыть папку с журналами».

Сохранение идёт **само**, с момента подключения. Ничего нажимать для
этого не нужно, и потерять данные, забыв сохранить, невозможно.

---

## Что показано на экране

| Поле | Что означает |
|---|---|
| Состояние | где ракета сейчас: готовность, разгон, подъём, апогей, снижение, посадка |
| Высота | текущая высота над площадкой, метры |
| Максимум | наибольшая достигнутая высота за полёт |
| Давление | атмосферное давление, паскали |
| Система спасения | безопасно, взведена или РАСКРЫТА |

Внизу три счётчика:

- **принято** — сколько пакетов дошло;
- **потеряно** — сколько пропало по дороге, считается по разрывам в
  номерах пакетов;
- **нечитаемых** — строки, которые пришли искажёнными.

Потери в несколько процентов при радиосвязи — обычное дело и о
неисправности не говорят.

## Станция и отладка (`vro_station.py`, Windows)

Новая программа с тремя режимами (боевой, отладка, прошивка). Запуск: двойной щелчок по
`СТАНЦИЯ И ОТЛАДКА.bat` в корне проекта или `python vro_station.py`.
Нужен Python 3 с tkinter, остальное лежит в проекте.

**Боевой (радио)** — подключить FT232RL с HC-12, скорость 9600. Крупно:
состояние, высота, максимум, давление, спасение, время борта, номер
пакета. Ниже график высоты, ошибки, события, счётчики (принято,
потеряно, повторов, испорчено), скорость пакетов и давность последнего.

**Отладка (провод)** — подключить плату RocketBoard USB-кабелем, скорость
115200. Живые показания борта (состояние, высота, ускорение, давление,
привод, напряжение батареи) и ручное управление приводом для наземной
отладки парашюта: «Закрыть серву» (слева) и «Открыть серву» (справа), цикл, угол 0–180° с шагом 20°, прогон
профиля полёта, сведения о плате, своя команда. Команды принимаются
только в состоянии READY, в полёте борт порт не читает.

**Снимок экрана**: кнопка «Снимок экрана (F12)» справа внизу (или клавиша F12)
сохраняет PNG всего окна программы в папку с журналами (`screenshot_<время>.png`),
рядом с CSV. Удобно прикладывать к разбору полёта. Ничего доустанавливать не
нужно: на Windows окно снимается системным вызовом, PNG собирается самой
программой (на Linux нужна утилита `import` из ImageMagick или Pillow).

**Журналы CSV** пишутся сами с момента подключения в `ground/logs/`
(`radio_*.csv` и `debug_*.csv`), после каждой строки на диск. Кодировка
utf-8 с BOM (Excel в Windows открывает русский текст корректно),
разделитель запятая. Колонка `kind` показывает, что за строка:

| kind | Что это |
|---|---|
| `packet` | новый пакет телеметрии (только радио) |
| `duplicate` | повтор уже принятого номера |
| `event` / `event_dup` | событие и его повтор |
| `bad` | испорчена в эфире, контрольная сумма не сошлась |
| `raw` | прочий текст (ответ HC-12 и т. п.) |
| `debug` | отладочная строка борта (только провод) |
| `text` | прочий вывод платы, например «привод -> DEPLOYED» |
| `command` | команда, ушедшая на борт |

**Отладка (радио)** — то же, что боевой режим, плюс кнопки управления платой
по радио, без провода: работает от батареи, USB не нужен. Кнопки: «Обнулить
высоту», «Закрыть серву» и «Открыть серву», цикл, углы, прогон профиля. Команда уходит кадром
`!номер|команда*CRC`, станция повторяет её до 6 раз, пока борт не подтвердит
(`@ACK`). Борт принимает такие команды только в состоянии READY и только в
наборе c_radio (в полётном d_full радиокоманд нет). HC-12 полудуплексный,
поэтому подтверждение иногда приходит не с первой попытки.

**Батарея в вольтах и процентах** (плитка «БАТАРЕЯ», боевой режим и отладка):
`9.31 В · 96 %`. Напряжение борт передаёт восьмым необязательным полем пакета
(сотые доли вольта; старые прошивки без поля тоже принимаются). Процент линейный:
0 % это 7,0 В (ниже стабилизатор уже не держит 5 В), 100 % это напряжение свежей
батареи. Кнопка «Батарея = 100 %» (внизу справа) принимает текущее напряжение за
100 % и запоминает его в `vro_settings.json`; принимает только 7,6–10,5 В, чтобы
не зафиксировать по ошибке питание от USB (около 4,2 В). Красным горит ниже 7,8 В,
серым «только USB?» при питании платы от USB. В CSV колонка `vbat_v`.

**Готовность к пуску.** Сверху крупная плашка: зелёная «ГОТОВ К ПУСКУ» только если
борт в READY, спасение взведено, нет критических ошибок и данные свежие. Красная,
если борт после посадки, парашют уже раскрыт, спасение не взведено, есть критическая
ошибка или нет данных (по неизвестному состоянию ракету не пускают). Жёлтая, если
батарея разряжена или ноль высоты не установлен. Кнопки, которые в текущем
состоянии борт всё равно проигнорирует, серые и не нажимаются: в посадке живёт
только «Вернуть в READY», при раскрытом спасении «Прогон профиля» выключен.

**Открыть парашют** (красная кнопка справа, только в боевом режиме; в режимах
отладки есть свои кнопки управления, дублировать их не нужно): на случай, если автоматика «зависла» в полёте. Команда `D` уходит по радио
и повторяется до 30 раз (до 12 секунд), пока борт не подтвердит. Борт принимает
её в любом состоянии, кроме «посадки», выдаёт раскрытие один раз (как резервное
по п. 14 ТЗ, событие `BACKUP_DEPLOY`) и подтверждает. Перед отправкой программа
спрашивает подтверждение. Работает **только на наборе c_radio**: в d_full
радиокоманд нет. Канал HC-12 полудуплексный, подтверждение зависит от дальности.
По USB в полёте плата команд не читает.

**Вернуть в READY** (кнопка в отладке): после посадки или после ручного
раскрытия парашюта на земле, по явной команде оператора, когда парашют сложен. Привод возвращается в SAFE, система спасения
взводится, высота обнуляется заново (около 8 секунд неподвижности). Итоги
прошлого полёта сохраняются в `summary_*.csv`, учёт нового идёт заново.

**После прогона профиля полёта** (и после настоящего полёта) борт остаётся в
состоянии «посадка» и команд не принимает: они работают только в READY. Борт
сам в READY не возвращается, это делает оператор вручную: перезагрузить плату
питанием. Программа пишет об этом прямо в окне, когда видит, что борт не в READY.

**Предполётное обнуление** (кнопка «Обнулить высоту», по проводу и по радио):
если высота «уехала» (температура, погода), борт заново ставит ноль. Ракету
нужно держать неподвижной около 8 секунд, светодиод мигает как при старте,
потом высота снова 0 и приходит событие GROUND_ZERO.

**Итоги полёта** (плитки под основными): апогей и время до него, скорость
сейчас, максимальная скорость подъёма, средняя скорость спуска на парашюте,
максимальное ускорение, время и высота раскрытия, время полёта. В радиопакете
ускорения нет, поэтому оно считается по высоте с барометра и это оценка,
занижающая пики. Настоящее ускорение видно только по проводу. По посадке
итоги печатаются в журнал событий, а при отключении сохраняются в
`summary_*.csv` рядом с журналом.

**Прошивка** — выбрать готовую прошивку (А, Б, В, Г или настройка HC-12) либо
свой `.hex`, выбрать порт платы сверху и нажать «Прошить плату». Программа
сама переводит плату в загрузчик, находит новый порт и пишет через avrdude,
вывод идёт в окно. Готовые прошивки берутся из `release/bin` (в `.exe`
они зашиты внутрь, вместе с `avrdude.exe`, ничего ставить не нужно).
Из консоли: `python3 vro_flash.py --firmware c_radio --port /dev/ttyACM0`.
После прошивки подождите 3 секунды и переключитесь в другой режим.

Без окна для проверки:

```sh
python3 vro_station.py --console --mode debug --port /dev/ttyACM0 --cmd "i,d,s"
python3 vro_station.py --console --mode radio --port /dev/ttyUSB0 --seconds 60
```

## Работа без окна

Пригодится, если программа запускается на компьютере без экрана или
через SSH.

```sh
python3 rocket_ground.py --list                          # показать порты
python3 rocket_ground.py --console --port /dev/ttyUSB0   # Linux
python3 rocket_ground.py --console --port COM3           # Windows
```

Остановка по Ctrl+C. Итог сеанса печатается при выходе.

## Проверка без ракеты и без радиомодуля

В комплекте есть имитатор борта: он выдаёт ровно такие же строки, какие
передаёт настоящая ракета. Можно проверить всю цепочку, не имея ничего,
кроме компьютера.

Самое простое — посмотреть, что вообще передаёт ракета:

```sh
python3 fake_rocket.py
```

Полная проверка приёма, через пару виртуальных портов (нужен `socat`,
есть в Linux и macOS):

```sh
# терминал 1
socat -d -d pty,raw,echo=0,link=/tmp/rocket_tx pty,raw,echo=0,link=/tmp/rocket_rx

# терминал 2 — «ракета»
python3 fake_rocket.py --port /tmp/rocket_tx

# терминал 3 — «земля»
python3 rocket_ground.py --console --port /tmp/rocket_rx
```

Ключ `--loss 0.2` заставит имитатор терять пятую часть пакетов: так
проверяется подсчёт потерь.

## Открыть журнал с карты памяти

Программа разбирает и файлы `FLTnnnn.CSV`, записанные бортом на
MicroSD. Формат журнала на карте отличается от радиопакета, но код
разбора общий, так что отдельной программы для этого не нужно.

## Формат данных

Пакет телеметрии (п. 22 ТЗ):

```
номер|время_мс|СОСТОЯНИЕ|высота|давление|СПАСЕНИЕ|флаги
642|12840|COAST|87.42|99584|ARMED|0
```

Событие (п. 33 ТЗ):

```
#12840|APOGEE_CONFIRMED
```

**Номер пакета** увеличивается ровно на единицу с каждым переданным
пакетом. Именно по разрывам в нём считаются потери.

Скорость порта — **9600**, заводская у HC-12. Если модуль перенастроен,
задать другую ключом `--baud`.

## Если что-то не работает

| Что видно | Что проверить |
|---|---|
| Список портов пуст | плата или переходник не воткнуты; нет драйвера — `ПРОШИТЬ ПЛАТУ.bat`, пункт «Установить драйверы» |
| Порт не открывается | порт занят другой программой; в Linux нужны права, помогает `sudo usermod -aG dialout $USER` и перезаход |
| Кружок красный, данных нет | ракета не включена, HC-12 перепутаны TX и RX, или модули настроены на разные каналы |
| Много «нечитаемых» строк | не совпадает скорость порта; проверить `--baud` |
| Потери близки к 100 % | ракета слишком далеко, или антенна не подключена |
| Не запускается окно | не установлен `python3-tk`; можно работать через `--console` |
