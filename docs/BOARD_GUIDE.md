# Инструкция по плате и датчикам

Практическое руководство: как подключать, как питать, что можно и чего
нельзя, как проверить исправность и как читать датчики.

Относится к плате **RocketBoard** (схема `DevBoard_Std_A3.pdf`) с
установленным модулем **Arduino Pro Micro** на ATmega32U4.

---

## 1. Что на плате

| Обозначение | Что | Установлено |
|---|---|---|
| U1 | Стабилизатор L7805, 9 В → 5 В | да |
| U4 | Arduino Pro Micro, ATmega32U4 | да |
| U5 | Посадочное место под GY-91 (MPU9250 + BMP280) | **нет** |
| U6 | Посадочное место под IMU-10DOF (ICM-20948 + BMP280) | **да** |
| U2 | Посадочное место под HC-12 | нет |
| U3 | Посадочное место под SV610 | нет |
| D1 | Диод SS14 на входе питания | да |
| D2 | Светодиод индикации | да |
| LS1 | Пьезоизлучатель | проверить на своей ревизии |

Под инерциальный модуль и под радиомодуль на плате предусмотрено **по
два альтернативных места**. Ставится одно из двух. Это важно помнить:
две платы из одной партии могут нести разные микросхемы.

---

## 2. Питание

### Как питать

```
9 В на разъём J1 или J3  →  диод SS14  →  L7805  →  +5 В на всю плату
```

Фильтрация: 1 мкФ на входе стабилизатора, 100 нФ на выходе.

Плата также питается от USB, когда подключена к компьютеру. Для
настольной работы этого достаточно.

### Измерение напряжения батареи

Делитель **20 кОм / 10 кОм**, коэффициент **1/3**, приходит на вывод
**A2** (порт PF5).

Пересчёт:

```c
float vbat = analogRead(A2) / 1023.0f * 5.0f * 3.0f;
```

Проверено: показание `ADC raw: 289` соответствует 4,238 В.

### Главное предостережение

> **Сервоприводы питаются от той же шины +5 В, что и контроллер.**

Бросок тока SG90 при трогании с места достигает сотен миллиампер и
просаживает питание всей платы.

**Сервопривод подключать до подачи питания, а не на ходу.** Подключение
к работающей плате 21.09.2026 привело к зависанию, на поиск причины
ушло время.

Если механика системы спасения окажется тугой, привод стоит питать
отдельно, а с платой соединить только сигнальный провод и землю.

## 3. Распиновка

Имена цепей на схеме **не совпадают** с именами выводов Arduino.
Например, цепь с подписью «A2» на разъёме J8 приходит на порт PF6, а
это вывод **A1** по нумерации Arduino. В таблице ниже приведены номера
именно в нумерации Arduino — те, что передают в `pinMode` и `analogRead`.

| Назначение | Цепь | Порт | Arduino | Разъём |
|---|---|---|---|---|
| SDA | SDA | PD1 | **D2** | к датчикам |
| SCL | SCL | PD0 | **D3** | к датчикам |
| Сервопривод 1 (спасение) | SERVO1 | PD7 | **D6** | J4 |
| Сервопривод 2 | SERVO2 | PB5 | **D9** | J6 |
| Светодиод | LED | PC6 | **D5** | на плате + J7 |
| Кнопка | BUTTON | PF4 | **A3** | J5 |
| Пьезоизлучатель | BUZZER | PB4 | **D8** | LS1 |
| Напряжение батареи | VBAT | PF5 | **A2** | делитель |
| Выбор кристалла MicroSD | CS | PD4 | **D4** | J9 |
| SCK | SCK | PB1 | **D15** | J9 |
| MISO | MISO | PB3 | **D14** | J9 |
| MOSI | MOSI | PB2 | **D16** | J9 |
| UART радио, приём | RX | PD2 | **D0** | U2/U3 |
| UART радио, передача | TX | PD3 | **D1** | U2/U3 |
| Режим настройки радио | SET | PE6 | **D7** | U2/U3 |

Выводы I2C и SPI у ATmega32U4 заданы аппаратно и перенесены быть не
могут.

### Разъёмы

| Разъём | Что |
|---|---|
| J1, J3 | Вход питания 9 В |
| J2 | Коаксиальный разъём антенны |
| J4 | Сервопривод 1: +5 В, GND, сигнал |
| J5 | Кнопка |
| J6 | Сервопривод 2: +5 В, GND, сигнал |
| J7 | Внешний светодиод |
| J8 | Дополнительные выводы: D10, A1, A0 |
| J9 | MicroSD по SPI: CS, SCK, MOSI, MISO, +5 В, GND |
| J10, J11 | Дополнительные разъёмы |

## 4. Инерциальный модуль ICM-20948

### Что важно знать сразу

> **Это не MPU9250.** Библиотеки и примеры для «GY-91» не подойдут.

Отличия, из-за которых чужой код не работает:

| | ICM-20948 | MPU9250 |
|---|---|---|
| `WHO_AM_I` | регистр `0x00`, значение `0xEA` | регистр `0x75`, значение `0x71` |
| Банки регистров | **четыре**, переключаются через `0x7F` | нет |
| `PWR_MGMT_1` | `0x06` (банк 0) | `0x6B` |
| Данные акселерометра | с `0x2D` | с `0x3B` |
| Магнитометр | AK09916 | AK8963 |

Если читать регистр `0x75` в надежде на `WHO_AM_I`, получите `0x40` —
бессмысленное значение, которое легко принять за неисправность.

### Адрес на шине

`0x68`. Вывод SA0 подтянут к земле. Альтернативный адрес `0x69` не
используется.

### Банки регистров

Перед обращением к настроечным регистрам банк выбирается явно:

```c
/* записать номер банка, сдвинутый на 4 бита влево */
writeReg(0x68, 0x7F, bank << 4);
```

| Банк | Что в нём |
|---|---|
| 0 | `WHO_AM_I`, управление питанием, **данные датчиков** |
| 2 | Диапазоны, фильтры, делители частоты |

После настройки обязательно вернуться в банк 0, иначе чтение данных
попадёт не туда.

### Последовательность инициализации

```c
selectBank(0);
readReg(0x00) → должно быть 0xEA        /* проверка микросхемы   */

writeReg(0x06, 0x80);  delay(100);      /* сброс                 */
selectBank(0);
writeReg(0x06, 0x01);  delay(30);       /* снять SLEEP           */
writeReg(0x07, 0x00);  delay(30);       /* включить все оси      */

selectBank(2);
writeReg(0x14, диапазон_аксель);        /* ACCEL_CONFIG          */
writeReg(0x01, диапазон_гиро);          /* GYRO_CONFIG_1         */
writeReg(0x00, 0x00);                   /* делитель частоты      */

selectBank(0);                          /* вернуться за данными  */
```

**Шаг «снять SLEEP» пропустить нельзя.** Заводское значение
`PWR_MGMT_1` равно `0x41`, бит `SLEEP` взведён, и микросхема молчит.
Если датчик отвечает на шине, но данные нулевые — почти наверняка забыт
этот шаг.

### Формат байтов настройки диапазона

И `ACCEL_CONFIG`, и `GYRO_CONFIG_1` устроены одинаково:

```
биты [5:3]  частота среза фильтра
биты [2:1]  диапазон
бит  [0]    включение фильтра, 1 = включён
```

| Диапазон акселерометра | биты [2:1] | Отсчётов на 1 g |
|---|---|---|
| ±2 g | 00 | 16384 |
| ±4 g | 01 | 8192 |
| ±8 g | 10 | 4096 |
| ±16 g | 11 | 2048 |

| Диапазон гироскопа | биты [2:1] | Отсчётов на 1 °/с |
|---|---|---|
| ±250 °/с | 00 | 131 |
| ±500 °/с | 01 | 65,5 |
| ±1000 °/с | 10 | 32,8 |
| ±2000 °/с | 11 | 16,4 |

Для ракеты берётся ±16 g: на ±2 g акселерометр уйдёт в насыщение на
старте, и момент старта определится неверно.

### Чтение данных

Одним запросом на 12 байт с адреса `0x2D` (банк 0):

```
байты 0..5    акселерометр X, Y, Z   по два байта, старший первый
байты 6..11   гироскоп     X, Y, Z
```

Значения знаковые, 16 разрядов. Делятся на коэффициент из таблицы выше.

### Смещение нуля гироскопа

Гироскоп в покое показывает не ноль. На имеющемся экземпляре замерено
**−0,65 °/с по оси Z** и −0,22 °/с по оси X.

Смещение обязательно снимать усреднением в неподвижном состоянии при
каждом включении, иначе оценка угла уедет.

### Ориентация осей: как определить без кабеля в корпусе

Задача из п. 47.4 ТЗ — понять, какая ось датчика направлена вдоль
продольной оси ракеты. Кажется, что для этого надо закрепить плату в
корпусе и снять показания, но в собранном корпусе не остаётся места под
провод USB.

Этого и не требуется. Оси датчика жёстко связаны **с самой платой**, а
не с корпусом. Поэтому работа делится на два независимых шага, и второй
электроники не требует вовсе.

**Шаг 1. На столе, плата отдельно, USB подключён.**

Залить `tools/imu_live` и по очереди положить плату каждой стороной вниз:

| Положение платы | Что покажет | Вывод |
|---|---|---|
| плашмя, микросхемами вверх | одна ось около **+1 g** | эта ось перпендикулярна плате |
| плашмя, перевёрнута | та же ось около **−1 g** | подтверждение и знак |
| поставлена на длинный край | другая ось около ±1 g | ось вдоль короткой стороны |
| поставлена на короткий край | третья ось около ±1 g | ось вдоль длинной стороны |

Записать результат: какая ось куда смотрит относительно платы. Этого
достаточно, дальше датчик не нужен.

**Шаг 2. Геометрия, без электроники.**

Посмотреть, как плата стоит в корпусе, и сопоставить с записью из шага 1.
Та ось платы, что смотрит в сторону носа ракеты, и есть продольная.

### Влияет ли это на полёт сейчас

**Нет.** Автомат полёта работает с **модулем** вектора ускорения:

```c
accel_mag = sqrt(ax² + ay² + az²)
```

Модуль от ориентации не зависит. Обнаружение старта, конца активного
участка и покоя при посадке одинаково сработают при любом положении
платы в корпусе.

Ориентация понадобится позже, если захочется:

- отделять продольное ускорение от бокового;
- оценивать угол отклонения от вертикали;
- разбирать полёт по отдельным осям.

Для первого полёта пункт 47.4 можно считать некритичным.

### Магнитометр

AK09916 находится внутри ICM-20948 и снаружи на адресе `0x0C`
не виден, пока не включён режим bypass битом `BYPASS_EN` в регистре
`0x0F` банка 0. У MPU9250 этот регистр имеет адрес `0x37` — ещё одна
причина, по которой чужой код молчит.

В текущей версии проекта магнитометр не используется: по п. 4.1 ТЗ он
не обязателен.

### Измеренные характеристики

| Величина | Значение |
|---|---|
| Шум модуля ускорения в покое | СКО 0,005 g, размах 0,010 g |
| Шум гироскопа в покое | около ±0,3 °/с |
| Показание модуля ускорения в покое | 1,00–1,01 g |

Акселерометр очень тихий: порог обнаружения старта в 2,5 g отстоит от
шума на сотни СКО.

## 5. Барометр BMP280

### Опознание

Адрес **`0x77`** (вывод SDO на питании). Регистр `0xD0` должен вернуть
**`0x58`**.

Соседнее значение `0x60` означало бы BME280 — та же микросхема плюс
влажность. Расчёт давления у них совпадает полностью, различается
только идентификатор и необходимость отдельно настроить канал влажности.

### Инициализация

```c
readReg(0xD0) → 0x58              /* проверка микросхемы          */
writeReg(0xE0, 0xB6); delay(10);  /* сброс                        */
читать 24 байта с 0x88            /* калибровочные коэффициенты   */
writeReg(0xF5, config);           /* фильтр и интервал простоя    */
writeReg(0xF4, ctrl_meas);        /* передискретизация и режим    */
```

Используемые значения:

- `config = 0x08` — интервал простоя 0,5 мс, аппаратный фильтр x4;
- `ctrl_meas = 0x2F` — температура x1, давление x4, непрерывный режим.

Даёт около 100 измерений в секунду, чего с запасом хватает.

### Калибровочные коэффициенты

Каждый экземпляр микросхемы несёт собственный набор из двенадцати
коэффициентов в регистрах `0x88`…`0x9F`. **Без них показания
бессмысленны.** Читаются один раз при инициализации.

Признак того, что прочитан мусор: коэффициенты `dig_T1` или `dig_P1`
равны нулю. У исправного экземпляра такого не бывает.

### Чтение и компенсация

Шесть байт с адреса `0xF7`:

```
байты 0..2   давление,    20 разрядов
байты 3..5   температура, 20 разрядов
```

**Температуру считать первой.** Её расчёт заполняет промежуточную
величину `t_fine`, без которой компенсация давления не работает. Это
частая ошибка: перепутали порядок — получили правдоподобное, но неверное
давление.

Берётся 32-разрядный вариант формулы компенсации, а не 64-разрядный:
у ATmega32U4 нет аппаратного умножения 64 бит, и такой расчёт занял бы
в разы больше времени. Потеря точности — единицы паскалей, то есть доли
метра.

Формулы реализованы в `firmware/src/drivers/bosch_pt.cpp` и взяты из
документации Bosch без изменений, включая порядок сдвигов. Переписывать
их «покрасивее» не стоит: арифметика подобрана так, чтобы не терять
разряды.

### Высота

Относительная высота считается от давления на площадке:

```
h = 44330 x (1 − (p / p0) ^ 0.1902949)
```

где `p0` — усреднённое давление, снятое при включении.

### Измеренный шум

| Величина | СКО | Размах за минуту |
|---|---|---|
| Давление | 2,8 Па | 13 Па |
| Высота, без фильтра | 0,244 м | 1,11 м |
| Высота, фильтр 0,35 | 0,199 м | 0,95 м |

Дрейф около 0,006 м/с, то есть 0,35 м в минуту. Для полёта длиной в
несколько секунд несущественно, но означает, что абсолютная высота
«уползает» и годится только как относительная.

**Все пороги, связанные с высотой, должны быть заметно больше 1 метра.**
Порог обнаружения апогея в проекте равен 2,0 м именно поэтому.

## 6. Шина I2C

Выводы: **SDA = D2**, **SCL = D3**. Заданы аппаратно.

Частота 400 кГц. На 100 кГц чтение 12 байт заняло бы около миллисекунды,
что слишком много для цикла на 50 Гц.

### Обязательная строка

```c
Wire.setWireTimeout(3000, true);
```

По умолчанию в библиотеке `Wire` проверка таймаута **отключена**
(`twi_timeout_us = 0`), и при залипании шины программа останавливается
навсегда. Второй параметр включает сброс шины по таймауту.

Для ракеты это вопрос безопасности: зависшая шина означает, что не
выполняется ничего, в том числе не выпускается парашют.

### Что должно быть на шине

```
0x68   ICM-20948
0x77   BMP280
```

Если устройств больше или меньше — искать неисправность до того, как
браться за программу.

## 7. Сервоприводы

Два разъёма: **J4** (вывод D6) и **J6** (вывод D9). В текущей версии
используется только первый, для системы спасения.

Питание +5 В с платы. Про риск просадки — раздел 2.

### Состояния

| Состояние | Что означает |
|---|---|
| `SAFE` | исходное безопасное положение |
| `ARMED` | система готова, ждёт полёта |
| `DEPLOYED` | команда на раскрытие выдана |
| `ERROR` | ошибка управления |

Углы `SAFE` и `DEPLOYED` задаются в `config.h`. Текущие значения 20 и
120 градусов **условны**: механики системы спасения пока нет.

### Питание привода снимается автоматически

После раскрытия программа держит привод под напряжением
`RECOVERY_SERVO_HOLD_MS` (по умолчанию 1200 мс), затем отпускает его.
Удержание под нагрузкой греет SG90 и сажает батарею.

### Проверка на столе

Через сервисный режим, команды `s`, `d`, `t` и цифры `0`…`9`. Подробнее
в [HANDOFF.md](HANDOFF.md), раздел 4.

## 8. Радиомодуль

На плате два альтернативных места: **U2** под HC-12 и **U3** под SV610.
Обоим идут одни и те же цепи, поэтому программе различать их не нужно.

Подключение: аппаратный UART **`Serial1`** на выводах D0 и D1. Это не
`SoftwareSerial` и не отдельная библиотека — обычный UART из состава
ядра.

Вывод **`SET`** на D7 переводит модуль в режим настройки. Полётная
прошивка его не трогает; им пользуется скетч `tools/hc12_setup`.

Проверенный экземпляр: HC-12 v2.6, 9600 бод, канал 001, режим FU3.
Настройка мощности и проверка канала — [RADIO.md](RADIO.md).

### Почему передача идёт вслепую

Определить присутствие модуля по одному UART невозможно: он не отвечает
ничем, пока не переведён в командный режим выводом `SET`. Поэтому борт
передаёт, не проверяя. Это безопасно: если модуля нет, байты уходят в
никуда, а передатчик UART всё равно не блокируется.

`Serial1` (радио) и `Serial` (отладка по USB) — разные устройства и друг
другу не мешают.

## 9. MicroSD

Разъём **J9**: CS, SCK, MOSI, MISO, +5 В, GND.
Выбор кристалла на выводе **D4**.

Модуль пока не куплен. При покупке учесть:

- карту форматировать в **FAT32** (библиотека собрана только под него);
- имена файлов в формате 8.3, программа создаёт `FLT0001.CSV`,
  `FLT0002.CSV` и так далее;
- на типовом модуле стоит стабилизатор 3,3 В, питание 4,5–5 В;
- согласование логических уровней с ATmega32U4 проверить до сборки
  (п. 47.10 ТЗ).

Существующие файлы программа не перезаписывает: подбирается первый
свободный номер.

## 10. Индикация и кнопка

**Светодиод** на выводе D5, на плате (D2 через R5 1 кОм) и на разъёме J7
для выносного. Мигает с разным периодом в зависимости от состояния:

| Период | Что означает |
|---|---|
| 100 мс | критическая ошибка |
| 500 мс | инициализация |
| 1000 мс | готовность, ждём старта |
| 250 мс | полёт |
| 200 мс | посадка, маячок для поиска |

**Кнопка** на A3, подтянута резистором 10 кОм. В текущей версии не
используется; назначение требуется утвердить (п. 29 ТЗ).

**Пьезоизлучатель** на D8. Включается только после посадки, чтобы ракету
было проще найти в траве. По умолчанию отключён флагом `HAS_BUZZER`:
наличие на конкретной ревизии не подтверждено.

## 11. Как проверить исправность платы

По порядку, от простого к сложному.

### Шаг 1. Плата видна на USB

```sh
arduino-cli board list
```

Ожидается `Arduino Leonardo` на `/dev/ttyACM0`, FQBN
`arduino:avr:leonardo`.

Брать FQBN `SparkFun:avr:promicro` **не нужно** — при нём не совпадёт
процедура сброса в загрузчик.

### Шаг 2. Датчики отвечают на шине

```sh
cd tools
arduino-cli compile --fqbn arduino:avr:leonardo hw_probe
arduino-cli upload -p /dev/ttyACM0 --fqbn arduino:avr:leonardo hw_probe
```

Ожидается:

```
устройство на 0x68
устройство на 0x77
всего: 2
```

### Шаг 3. Датчики опознаются

`tools/imu_id` снимает полный дамп регистров инерциального модуля.
Регистр `0x00` должен вернуть `0xEA`.

### Шаг 4. Датчики выдают осмысленные данные

`tools/imu_live` выводит живые показания. **Главный признак
исправности — модуль вектора ускорения в покое равен 1,00 g.**
Если он заметно отличается, неверен масштабный коэффициент или
неверно опознана микросхема.

### Шаг 5. Прошивка целиком

Залить набор A, дождаться `READY` и убедиться, что `err=0x0`, высота
держится около нуля, модуль ускорения около 1,00 g. Затем прогнать
тестовый профиль командой `r`.

## 12. Частые неприятности

| Симптом | Вероятная причина |
|---|---|
| Плата не отвечает после подключения привода | просадка питания, см. раздел 2 |
| Плата замолчала навсегда, USB исправен | залипла шина I2C, нужен `setWireTimeout` |
| Датчик виден, но данные нулевые | не снят бит `SLEEP` в `PWR_MGMT_1` |
| `WHO_AM_I` вернул `0x40` | читается регистр `0x75` вместо `0x00` |
| Высота скачет на метр | это штатный шум барометра, см. раздел 5 |
| Давление правдоподобное, но неверное | температура считается после давления |
| Пустой вывод сразу после заливки | подключились к порту загрузчика, нужна пауза |
| Вывод пропал совсем | печать в `setup()` или порог больше 64 байт |
| Все наборы одного размера | `arduino-cli` не применил флаги сборки |
